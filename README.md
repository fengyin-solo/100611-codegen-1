# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 动火与受限空间作业许可

作业许可不走通用流转，全部规则收在 `frontend/src/api/permit-service.ts`：

- **状态机**：作业票只能沿 申请 → 待检测 → 已签发 → 作业中 → 终结归档 顺序流转；
  跳级当场驳回并在提示里指出当前停在哪一段；已终结的票只能补附件，回不到作业中。
- **原始记录为准**：气体检测结论取 `gasTest`、监护人签到取 `guardian`，票面手填值不作数；
  签发时缺检测记录或结论不合格、开工时缺签到，整票退回「申请」段并标异常。
- **监护人裁决**：一名监护人同一时刻只能监护一张未终结的票；动火与受限空间共用一名
  监护人时受限空间优先开工（气体环境变化快、被困救援难度大，监护人须全程值守入口），
  被挤下的动火票退回待检测，裁决理由写进签发说明。
- **幂等与事务**：同一张票重复提交签发只生效一次（按签发批次识别），不重复落台账；
  签发/终结与整改台账写入放在一次 `saveBatch` 里，落库失败整套撤回。
- **整改台账**：签发、终结、退回、迁移的结论都写 `rectification`，安全巡检页与作业许可页
  都经 `listRectifications()` / `countOpenPermits()` 读同一份，未终结作业数只有一个口径。
- **存量迁移**：首次打开按作业日期升序回填重编号，只跑一次（`permitMeta` 记录）；已到
  「已签发」及以后的票缺检测记录时，取作业日期当天洞内通风机组运行中且有害气体未超限的
  记录补录为合格（标注迁移补录），当天无合格通风记录可依据的整票退回「待检测」并标异常；
  「作业中」的票缺签到按票面监护人补录。

状态机规则有冒烟测试：`frontend/test-permit.ts`，运行方式见文件头注释。
