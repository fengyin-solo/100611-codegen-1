# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 作业许可（动火与受限空间）规则

作业许可不走通用流转，统一由 `frontend/src/api/permit-service.ts` 管控：

- 状态机固定为 申请→待检测→已签发→作业中→终结归档，只能逐级往下转；跳级当场驳回，
  驳回信息里指出当前停在哪一段、下一步只能做什么。
- 气体检测结论、监护人签到只认原始记录（`gascheck`、`guardian` 两个集合）；签发时检测
  没出结论、开工时监护人没签到，都整票退回「申请」并记异常，补齐后重走流程。
- 共用监护人裁决：**受限空间优先于动火**（舱内气体环境随时间变化、检测结论时效短、救援
  难度大，动火作业环境相对开放可延后），同类型按申请先后（票号小者优先）；裁决理由在
  签发时写进「签发说明」，开工时强制执行，且一名监护人同时只能监护一处作业。
- 已终结归档的票只能补附件，回不到「作业中」。
- 重复提交只生效一次：每个写操作带 requestId 进幂等日志，重复提交按首次结果处理；
  同一张票重复签发也只生效一次。所有写操作包在事务里，落库失败整套撤回。
- 冲突时以数据层已落库的状态为准（先落库者为准），后到且冲突的请求驳回，不改写已有结论。
- 签发、终结的结论自动落到安全巡检的整改台账（`XC-<票号>` 待整改 → 终结后闭环）；未终结
  作业数与列表只有 `permit-service.ts` 一个取数口，作业许可页与安全巡检页读的是同一份。
- 存量纸质票按作业日期迁移回填：日期已过且检测、签到齐全 → 终结归档；日期已过但缺记录 →
  待检测并记异常；日期未到 → 待检测。缺检测记录的一律生成来源标注「存量补录」的占位检测
  记录（结论留空，不算结论），补录结论时原地补齐、不另起一条，补齐前不许签发。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。
